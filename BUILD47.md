# Build 47

Package governance acquired an economy. Every Build 46 namespace now has a persistent treasury with a balance, maintenance debt, dependency-tax rate, payroll requirement, sponsor history, bailout history, and funding status. Live Build 45 SBOM usage and reverse dependency relationships become economic activity: packages that are used by more deployed artifacts and downstream packages can collect more dependency-tax revenue, while active maintainers and vulnerability pressure increase maintenance cost. Paying maintainers reduces fatigue; missed payroll converts technical dependence into financial debt rather than immediately stopping execution.

Maintenance labor can now stop while software keeps running. Underfunded namespaces can enter a maintainer strike, freezing ordinary package governance while old signed artifacts, SBOMs, consensus nodes, and production replicas continue executing the package. Continued debt can produce package insolvency, creating a bankrupt dependency that still has live users. Strikes can be settled through dependency-commons grants or emergency bailouts. Bailouts restore maintenance without erasing the debt, strike, or previous execution history, and repeated emergency rescues can give the emergency software treasury growing influence because the package has become too critical to fail.

Namespaces can also accept persistent sponsorship contracts from archive foundations, administrative consortia, court infrastructure funds, downstream cooperatives, elected offices, or the other reality's interoperability fund. Sponsorship pays into the package treasury over time. Once a sponsor supplies enough of the package's effective financing, Build 47 creates a real sponsor-steward maintainer identity and inserts that identity into open Build 46 succession cases with funding-derived votes. Package financing can therefore become package governance without pretending that the sponsor authored the source code. Places such as `maintainer salary became a governance vote` and `package budget with a foreign policy` mark sponsor capture.

Dependency taxes can be raised or lowered. Excessive taxation can provoke a downstream tax revolt: current package users create a rival same-name package lineage and a downstream-cooperative maintainer, forcing the namespace back into Build 46's split-governance state. Funding thus joins security, registry policy, and maintainer succession as another reason a package can fork while both lineages remain historically real.

Build 47 tracks package treasuries, maintenance balances, debt, payroll, dependency taxes, sponsorship contracts, sponsor influence, sponsor-steward identities, maintainer strikes and settlements, dependency-commons grants, emergency bailouts, package insolvencies, funding-driven forks, funding audits, sponsor capture, and package-funding crises. Crises can create places such as `critical package on strike while production continues`, `bankrupt package still running the state`, `dependency declared too critical to fail`, `budget committee beneath the trust root`, and `critical dependency priced itself into sovereignty`, leaving the bailiff asking who funds the package that funds the government.
