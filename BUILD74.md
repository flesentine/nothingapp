# Build 74

Public deficiency acquired multilateral recapitalization. Build 73 allowed a Build 63 investment fund to disappear while the Build 55 monetary authority still held the unpaid rescue facility and the monetary base created by Build 70 remained outstanding. Build 74 connects that orphaned public loss back to the much older Build 58 stabilization reserve pool and Build 59 quota-weighted board through the Interreality Monetary Recapitalization Window.

A Build 73 case remains historically `liquidated-deficiency`. Build 74 does not reopen the receivership or pretend the failed fund repaid anything. Instead it computes the current economic deficiency as the smaller of the historical Build 73 deficiency, the still-outstanding Build 71 public recoupment amount, and the still-outstanding linked Build 55 facility principal. If the public facility has already been repaid from another source, the Build 73 deficiency can become economically cured without any stabilization-pool transfer.

An eligible deficiency can create a real Build 59 `MOT#` board record of type `monetary-recapitalization74`. The motion lives in the existing `S.fundMotions59` history, uses the existing Build 59 board majority threshold, and records the target reality as recused from voting on its own bailout. Build 74 uses dedicated motion statuses such as `pending-recap74` and `deadlocked-recap74` so the older Build 59 vote code can display the motion without accidentally applying its unrelated legacy vote-preference model.

The recapitalization currency is the target reality's own currency already held in the Build 58 stabilization pool. A Reality A deficiency therefore draws from `poolRA`; a Reality B deficiency draws from `poolRB`. Those pools were originally created from the other reality's foreign-reserve contribution, so recapitalization converts the stabilization system from a balance-of-payments lender into a cross-reality loss-sharing mechanism.

Voting is intentionally difficult. The target reality is recused. With an ordinary 50/50 Build 59 board, the non-target director can vote yes with only 50% of total quota weight, below the 60% board threshold. The motion therefore deadlocks even though nobody votes no. A recap can pass normally only if the non-target reality already has enough quota weight to cross the board threshold by itself.

A deadlocked or still-pending recapitalization can instead use the old Build 59 systemic-necessity idea. The stabilization chair may override the missing majority. Build 74 increments the existing Build 59 chair-power and board-override counters and reduces the Build 58 fund's independence and credibility using the same penalties as the older governance override. The override is therefore a governance cost, not free funding.

Once approved, the stabilization fund surrenders the target reality's pooled currency back into the public monetary balance sheet. The transfer reduces the linked Build 55 facility principal and the target authority's monetary base one-for-one. If the facility is still active, outstanding credit falls as well. Build 55 reserve-extinguishment totals increase by the same amount. The failed Build 63 fund does not receive cash and the Build 73 liquidation record does not change.

Build 74 also reduces the current Build 71 deficiency amount and records the amount socialized through the stabilization pool. The Build 71 claim keeps its historical `receivership-deficiency73` status even when economic outstanding reaches zero. Likewise the Build 73 case stays `liquidated-deficiency`, but receives `economicDeficiencyRemaining74` and `economicDeficiencyCured74` fields so historical insolvency and later public loss-sharing can both remain true.

If facility principal reaches zero, Build 74 marks that principal recapitalized. An active facility with no remaining interest becomes `repaid-by-stabilization74`; a previously monetized facility with no remaining interest becomes `extinguished-by-stabilization74`. Existing accrued Build 55 interest is not silently forgiven: if interest remains, the old facility status survives even after principal is recapitalized.

The deterministic default-board harness starts from the Build 73 tiny-estate deficiency of 0.4719418182 in Reality A. The Build 59 board is 50/50. Reality A is recused, Reality B votes yes with 50 weight, and the 60% threshold is not reached. The motion becomes `deadlocked-recap74`, the stabilization pool remains unchanged, and the Build 55 facility and monetary base remain 0.4719418182.

The chair-override harness applies systemic necessity to that same deadlock. Build 74 transfers exactly 0.4719418182 RA from the stabilization pool, reducing `poolRA` from 5.0 to 4.5280581818. The Build 55 facility principal and monetary base both fall to zero, Build 55 reserves extinguished increase by 0.4719418182, and the Build 71 current outstanding amount becomes zero. The Build 73 case still reads `liquidated-deficiency` with historical deficiency 0.4719418182, but `economicDeficiencyRemaining74` becomes zero and the case is marked economically cured.

A quota-majority harness gives Reality B 65% of Build 59 votes. Because Reality A remains recused, Reality B alone crosses the 60% threshold. The motion passes as `passed-recap74` and the same 0.4719418182 transfer occurs without a chair override.

An insufficient-pool harness leaves only 0.20 RA available. A valid 65% majority approves the recap, but Build 74 can transfer only 0.20. The recap becomes `implemented-partial`, `poolRA` falls to zero, and 0.2719418182 remains in the Build 71 current deficiency, Build 55 facility principal, monetary base, and Build 73 economic deficiency.

A monetized-facility harness confirms that recapitalization also works after Build 55 has already converted the rescue into permanent money. Principal can be reduced to zero and monetary base extinguished while old accrued interest remains attached to the monetized facility. A separate external-repayment harness sets the Build 55 principal to zero before any recap request; Build 74 creates no request, marks the Build 73 deficiency economically cured, and records that public credit was repaid elsewhere.

Build 74 persists through `nothing-state-v74`, wraps the existing save/render chain, loads after `fund_resolution.js`, and extends forget-through-v74. It reads and selectively updates Build 55 monetary facilities and monetary base, Build 58 stabilization pools and governance credibility, Build 59 board motions/votes/deadlocks/overrides, Build 71 current recoupment amounts, and Build 73 deficiency records. Build 70 rescue history, Build 69 clearing history, and the Build 73 liquidation status remain intact.

New places include `foreign reserve pool absorbing a central bank loss from somebody else's investment fund`, `the bailout crossed the rift after the fund itself was already gone`, `other reality's reserve contribution disappearing into a failed fund bailout`, and `central bank rescue money extinguished by surrendering pooled reserves across the rift`. `multilateral_recap.js` passes V8 syntax validation. The instrumented harness executes the exact committed Build 74 functions and covers default recusal deadlock, chair override, quota-majority approval, partial pool funding, monetized-facility treatment, and externally repaid deficiency recognition.
