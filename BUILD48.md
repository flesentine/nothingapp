# Build 48

Package economics acquired procurement. Every Build 46 namespace can now open a persistent solicitation for outside maintenance of the package that already underpins live Build 44 artifacts. Competitive procurements generate multiple vendor profiles and bids with price, security, continuity, compatibility, sovereignty, and delivery characteristics. Each solicitation has a weighted evaluation rubric, bid history, winner, audit trail, and eventual vendor contract. This turns package maintenance from an informal funding relationship into an institutional purchasing decision whose paperwork can itself influence which implementation becomes canonical.

A bidder can be allowed to help draft the evaluation criteria before bids are scored. The resulting rubric shifts weight toward that bidder's strongest attributes and reduces the importance of price. The later evaluation remains mathematically consistent with the published criteria, so a captured procurement can produce a formally correct winner even though the winner helped define what "best value" meant. If that same bidder wins, Build 48 records procurement capture and can create places such as `winning vendor wrote the evaluation rubric` and `best value according to vendor spreadsheet`.

Awards create real vendor-contractor maintainer identities inside Build 46 rather than merely storing a company name. Contracts have value, payments, performance, renewals, breaches, expiration, sole-source status, and a growing lock-in score. A vendor can publish a new package release under the authority of the awarded contract; that release can become the namespace's canonical package. Deploying the contract release creates new Build 44 artifacts, dependency locks, hashes, provenance attestations, trust-audit records, and Build 45 SBOMs while preserving old artifacts and vulnerabilities in history.

Reality can also bypass competition. A package whose treasury is on strike or bankrupt can receive a sole-source continuity award, and an ordinary competitive solicitation can be converted to sole source manually. Existing Build 47 sponsor capture can bias the preferred sole-source vendor. Repeated renewals without rebidding and repeated live rebuilds increase vendor lock-in until terminating the vendor would require rebuilding reality around another package lineage. A vendor may be debarred after breaches, but debarment does not uninstall binaries it already delivered.

Build 48 tracks procurements, evaluation criteria, vendors, bids, criteria authorship, competitive and sole-source awards, vendor-contractor maintainer seats, contracts, payments, contract releases, production rebuilds, performance, breaches, renewals, debarment, procurement audits, vendor lock-in, procurement capture, and procurement crises. Crises can create places such as `RFP became a constitutional instrument`, `sole-source software contract`, `contract termination now requires rebuilding reality`, and `best value became source of authority`, leaving the bailiff asking whether the contract or the package is sovereign.
