# Build 70

Clearing shortfalls became monetary policy. Build 69 moved Build 68 recovery-note default swaps into the old Build 54 central counterparty, which reduced bilateral dealer risk by making a shared clearinghouse responsible for the payout. The new failure mode was a `final-with-shortfall` recovery settlement that froze the CCP after its seller collateral, dealer capital, member margin, default fund, survivor assessments, and CCP capital were exhausted. Build 70 connects that new arrears category to the much older Build 55 lender-of-last-resort system through the Interreality Recovery Settlement Reserve Window.

Build 55 already knew how to lend to a stressed or frozen Build 54 CCP and how to create reserves after an ordinary Build 54 settlement cycle was declared final with unpaid arrears. It did not know that Build 69 had created a second kind of clearing shortfall. Build 70 does not rewrite Build 55. Instead it creates real Build 55 liquidity-facility records, reserve-account entries, monetary-base growth, outstanding central-bank credit, emergency-loan counts, make-good records, collateral quality, and negative-equity consequences for recovery-clearing rescues.

A Build 69 `final-with-shortfall` settlement can be opened at the new recovery monetary window. The unresolved amount is the historical Build 69 shortfall minus any prior Build 70 make-good. The old settlement status remains `final-with-shortfall` even after public money arrives. Build 70 adds `economicArrearsCured70`, `economicShortfall70`, and linked make-good records rather than changing the historical clearing decision. Procedural finality and eventual payment therefore remain separate facts.

The borrowing institution is the existing Build 54 CCP. Build 70 values collateral as future clearing-member assessment capacity plus the CCP guarantee fund, then applies the same Build 55 grade ladder and haircut schedule. An operating CCP is treated as A, stressed as BBB, frozen as BB, and failed as B. The existing Build 55 authority collateral floor therefore matters directly. A frozen Build 69 CCP is normally BB while the default authority floor is BBB, so an ordinary recovery-window loan is refused even when the nominal collateral face looks large enough.

The user can explicitly invoke an emergency collateral override. That creates a real Build 55 `LF#` facility with `borrowerType:'ccp'`, the recovery settlement as its collateral reference, the Build 55 authority's discount rate plus stress and collateral surcharges, the ordinary Build 55 maturity and accrual fields, and `recoveryBridge70:true`. The authority's monetary base and outstanding credit increase by the rescue principal, the CCP receives the reserves, and those reserves are immediately used to pay the Build 63 fund the unresolved Build 69 settlement amount. A linked Build 55 `MGP#` make-good record is also created, so the old monetary system's global make-good count includes this new category.

Emergency lending is not free policy. An override increments the authority's emergency mandate and reduces independence and credibility. Lending to an insolvent CCP uses the existing Build 55 insolvent-loan count and applies the older solvency-override credibility penalty. If the recovery-clearing collateral is below the amount lent, the gap becomes bad collateral on the existing monetary authority balance sheet. Build 70 recomputes outstanding Build 55 credit and bad assets after the rescue; if bad recovery-clearing collateral exceeds authority capital, the same authority can enter `negative-equity`.

Once a Build 70 facility exists, it is intentionally shaped like every other Build 55 facility. Build 55's older accrual, maturity, repayment, collateral-revaluation, forbearance, monetization, and negative-equity logic can therefore discover it later without a special parallel monetary universe. The collateral type remains `future clearing-member assessments and guarantee-fund receivable`, while later Build 55 surveillance can still revalue the borrowing CCP using its own older rules. A recovery-clearing rescue can become an evergreen lender-of-last-resort loan or permanent monetary asset if the CCP never rebuilds enough cash to repay.

Build 70 also preserves the recursive double-recovery chain. A non-naked Build 69 hedge may receive only a partial CCP payout and then receive a Build 70 public make-good for the shortfall. Build 67 deliberately preserves the assigned subrogation stream after default. If that recovery note later becomes `recovered-after-default`, Build 70 does not claw back the public rescue or reverse the recovery. It records a public double-recovery event: the fund received public settlement reserves because its hedge settlement failed and later received the surviving private recovery stream as well.

The deterministic main harness starts from the Build 69 exhausted-waterfall example with a 0.72 unresolved recovery-clearing shortfall and a frozen CCP. The ordinary recovery window refuses the loan because the frozen CCP is BB against the authority's BBB collateral floor. The emergency override creates a 0.72 real Build 55 facility, raises the monetary base and outstanding credit by 0.72, pays the fund 0.72, reopens the CCP when no other recovery-clearing arrears remain, and leaves the original Build 69 settlement status unchanged at `final-with-shortfall` while `economicArrearsCured70` becomes true.

The same harness then lets the Build 67 note become `recovered-after-default` with 2.2110784 of later assigned recovery. Build 70 records one public double-recovery event with the 0.72 public make-good and the separate 2.2110784 later recovery. No cash is invented at that observation step; the event records that two previously independent cash paths both remained historically valid.

A bad-collateral harness removes the CCP guarantee fund and surviving-member assessment capacity, increases the recovery-clearing shortfall to 5.0, and leaves the monetary authority with only 0.2 capital. An emergency override still creates the 5.0 facility, but the collateral is worth only 0.68 after the frozen-CCP haircut. The resulting 4.32 bad-asset gap exceeds monetary-authority capital and pushes the existing Build 55 authority into `negative-equity`.

Build 70 persists through `nothing-state-v70`, wraps the existing save/render chain, loads after `recovery_clearing.js`, and extends the forget action through version 70. It reads and selectively updates Build 54 CCPs and clearing members, Build 55 monetary authorities/facilities/reserve accounts/make-goods, Build 63 fund cash, Build 67 recovery notes, and Build 69 positions and settlements. It does not erase Build 69 shortfalls, Build 68 protection contracts, Build 67 defaults, Build 66 subrogation, or Build 65 title history.

New places include `central bank reserves paying a default swap on insurance recovery`, `private settlement finality repaired with public money afterward`, `public money arrived after recovery settlement was already final`, `central bank made a default swap whole without changing its failed settlement record`, and `taxpayer-like settlement reserves financed a hedge before the recovery later succeeded`. `recovery_monetary.js` passes V8 syntax validation. The instrumented harness executes the actual Build 70 functions and covers ordinary-rule refusal, emergency collateral override, real Build 55 facility creation, monetary-base growth, economic make-good without historical rewrite, public double recovery, bad collateral, and monetary-authority negative equity.
