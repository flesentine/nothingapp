# Build 68

The insurance recovery acquired insurance. Build 67 turned a Build 66 subrogation claim into a real Build 52 bond owned by a Build 63 investment fund. That created a useful mismatch with the old Build 53 derivatives market: Build 53 can already see the recovery note because it is an ordinary `S.softwareBonds52` obligation and its default observer will propagate a `status='default'` bond into existing swaps and securitization pools, but Build 53's holder model only knows treasuries, insurers, and derivatives dealers. It does not know the Build 63 fund that actually bought the recovery note. Build 68 adds the Interreality Recovery Default Swap Desk to bridge that gap without rewriting Build 53's historical contract model.

A Build 63 recovery-note investor can now hedge an active Build 67 note with a recovery default swap sold by one of the existing Build 53 derivatives dealers. The fund pays a one-time premium from its own cash, the Build 53 dealer receives the premium into dealer capital, and part of the dealer's existing collateral balance is segregated behind the new protection contract. The contract references both the Build 67 note and its shared Build 52 bond. If the note repays without a credit event, the protection expires and the segregated collateral returns to the dealer.

Build 68 also permits naked recovery protection. Another Build 63 fund can buy protection on a recovery note it never owned. The naked notional is larger than the note holder's ordinary hedge and receives a premium surcharge. Multiple different funds can stack naked protection on the same note. Build 68 counts its own contracts together with any native Build 53 credit swaps already referencing the same Build 52 bond. If gross protection exceeds 2.5 times the recovery note's face, the system records a synthetic-leverage crisis. A single expected recovery can therefore support more default claims than money expected to be recovered.

A Build 67 `defaulted-assignment` is a Build 68 credit event. The same event also sets the shared Build 52 bond to `default`, so old Build 53 contracts that already reference that bond remain free to react through their own pre-existing default observer. Build 68 settles its fund-native recovery swaps separately because Build 53 cannot credit a Build 63 fund directly. Settlement uses a 40% recovery assumption, matching Build 53's ordinary software credit swaps: 60% of swap notional is due. Segregated dealer collateral pays first and dealer capital pays the remainder.

The central consequence is that Build 67 deliberately preserves the assigned subrogation stream after default. A note can default because a downgrade collateral call failed and still later receive money from Build 66 as the insurer finally collects from the first clearing house. Build 68 does not reverse the earlier default-swap settlement when that happens. For a hedged note holder, it instead records a double-recovery event: the fund received cash-settled protection at default and later received the surviving assigned recovery stream. The historical default, the protection payout, and the later recovery all remain true at once.

Naked protection makes the same event stranger. A fund that never owned the recovery note can receive a default payment simply because the note defaulted, while the actual note investor keeps the assigned recovery claim and may later recover as well. This makes the causal stack recursive: a title insurer paid a sovereign ownership loss, sold its right to recover from a clearing house, and somebody else then bought insurance on the debt backed by that insurance recovery.

Build 68 uses real Build 53 dealer balance sheets rather than inventing new dealer capital. If a recovery-swap payout exhausts the seller, the dealer becomes `default`. Its active old Build 53 credit swaps become `counterparty-default`, and old Build 53 collateral-reuse chains sourced from that dealer are called. A receiving dealer loses the reused collateral amount and can itself fail if the recall drives capital below one. Active Build 68 swaps sold by the failed dealer close against whatever segregated collateral remains. A recovery-note hedge can therefore transmit losses backward into software derivatives contracts written long before sovereign title insurance existed.

The deterministic hedge harness used the Build 67 main note with 2.2110784 face and an AA grade. Clearing Yield Cooperative bought a full 2.2110784 hedge for a minimum 0.08 premium from A Archive Clearing House. The dealer segregated about 0.37367225 of its Build 53 collateral. When the recovery note defaulted, the swap owed 1.32664704 and paid it in full. The fund's cash moved from 20 to 19.92 after premium and then to 21.24664704 after the default payout. When the note later became `recovered-after-default` with 2.2110784 of assigned recovery paid, Build 68 recorded that entire 2.2110784 as later recovery in addition to the already-final protection settlement.

The synthetic harness created a separate 2.0 recovery note and let three different non-owner Build 63 funds buy 3.0 of naked protection each. Gross Build 68 protection reached 9.0 on 2.0 of recovery-note face and tripped the 2.5× synthetic-leverage rule. A compatibility check added an existing native Build 53 swap with 1.5 notional against the same Build 52 bond; Build 68 included it in the same gross-protection calculation, producing 4.5 gross notional after one new 3.0 naked contract.

The dealer-contagion harness then reduced the seller to 0.2 capital before one naked contract settled. The dealer defaulted. An unrelated active Build 53 credit swap sold by that dealer became `counterparty-default`; an old Build 53 collateral-reuse chain sourced from the dealer was called; and the receiving dealer lost 2.0 capital. The failed seller's other active Build 68 protection contracts closed against their segregated collateral. A separate no-credit-event harness confirmed that a normally repaid note expires its protection and returns all reserved collateral to the dealer.

Build 68 persists through `nothing-state-v68`, wraps the existing save/render chain, loads after `recovery_notes.js`, and extends the forget action through version 68. It reads and selectively updates Build 52 recovery-note bonds, Build 53 dealer capital/collateral, old credit swaps and collateral-reuse chains, Build 63 fund cash, and Build 67 recovery-note state. It does not rewrite Build 53's old swap records, Build 67 defaults, Build 66 recoveries, or Build 65 title disputes.

New places include `insurance on the note backed by insurance recovery`, `recovery-note investor hedged the insurer recovery it already bought`, `default protection without owning the recovery note`, `recovery-note default paid a derivative while recovery rights remained alive`, and `default paid once through protection and again through recovered subrogation`. `recovery_derivatives.js` passes Node syntax validation. The instrumented harness executes the actual Build 68 functions and covers fund-native hedging, naked synthetic leverage, native Build 53 notional compatibility, default settlement, later double recovery, no-credit-event collateral release, dealer failure, old Build 53 swap counterparty default, and old Build 53 collateral-reuse contagion.
