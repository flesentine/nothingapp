# Build 76

Creditor control acquired replenishment assessments. Build 75 allowed a member that absorbed enough Build 74 recapitalization losses to acquire a Build 59 voting majority without restoring the stabilization reserve pool those losses depleted. Build 76 gives that loss-born majority a new use through the Interreality Stabilization Replenishment Authority: a dominant creditor can compel the other reality to make a reserve contribution back into the fund.

An eligible assessment starts from a Build 75 `LQC#` loss-quota credit whose burden reality currently holds at least the old Build 59 board threshold, normally 60%. Build 76 does not treat a historical majority crossing as permanent authority; it recomputes current votes with the same Build 59 quota-score formula before an assessment can be requested.

Each assessment creates a real Build 59 `MOT#` motion of type `reserve-replenishment76`. The assessed reality is recused. The loss-bearing creditor votes yes. Build 76 uses dedicated statuses such as `pending-assessment76`, `deadlocked-assessment76`, and `implemented-assessment76`, so the old Build 59 vote routine can retain and display the motion without accidentally executing its unrelated legacy preference logic.

The assessment amount equals the Build 75 loss-quota credit that created the creditor's claim to governance capital. Payment is a mandatory version of the old Build 59 quota subscription. The assessed reality transfers its actual Build 56 foreign reserves into the Build 58 stabilization fund, increases its historical contributed-reserve field by the same amount, and receives one-for-one Build 58 quota. Build 76 does not mint reserves, create a Build 55 monetary asset, or refill a pool without taking reserves from a member.

The currency of replenishment is intentionally different from the currency of the original Build 74 loss. A Reality A recapitalization consumes RA from `poolRA`, reserves historically supplied by Reality B. If Reality B's loss-created majority later assesses Reality A, Reality A can pay only the foreign reserves it owns, RB. The compulsory payment therefore increases `poolRB`, not `poolRA`. Total stabilization resources can recover while the fund's currency composition becomes more mismatched.

Assessment payment also changes governance immediately. Build 76 reruns the actual Build 59 quota-score formula after every payment and updates the existing Build 58 quota-vote and Build 59 director-vote fields. Because the assessed member receives quota and contribution credit for paying, the assessment can destroy the creditor majority that imposed it. Build 76 records this as a creditor-majority reversal rather than inventing a separate voting system.

The deterministic full-payment harness begins with Reality A quota 10, Reality B quota 20, Reality A holding 10 RB of foreign reserves, and a 10.0 Build 75 loss-quota credit for Reality B. Before assessment, Build 59 weights are A 36.7088607595% and B 63.2911392405%. B can therefore impose the assessment while A is recused.

The motion passes with 63.2911392405 yes votes and zero no votes. Build 76 immediately collects all 10.0 RB from Reality A. `poolRB` rises from 5 to 15, A quota rises from 10 to 20, A `contributedRB` rises from 0 to 10, and A foreign reserves fall from 10 to zero. After the mandatory subscription, votes become A 54.0229885057% and B 45.9770114943%. The assessment is fully `paid`, the motion becomes `implemented-assessment76`, one creditor-majority reversal is recorded, and the reserve-exhaustion stress path is triggered.

The partial-payment harness gives Reality A only 2.0 RB against the same 10.0 assessment. B begins at 65.9630606860%, the motion passes, and Build 76 collects all 2.0 available reserves. `poolRB` rises from 5 to 7, A quota rises from 10 to 12, A reserves fall to zero, and 8.0 remains in assessment arrears. B still holds 61.1620795107%, so the creditor majority survives the partial payment.

A no-majority harness gives Reality B only 54.6875% of current votes. The same historical loss credit is not enough to authorize a new assessment: Build 76 creates no assessment and no Build 59 motion.

The live cross-build harness executes the exact committed Build 74 and Build 76 logic together. B starts at 63.2911392405%, imposes the full 10.0 assessment on A, and falls to 45.9770114943% after A pays. A new 0.5 Build 73 deficiency then enters Build 74. A is recused from its own recapitalization; B votes yes with only 45.9770114943%. The recap motion becomes `deadlocked-recap74`, no chair override occurs, and the new Build 55 facility principal and monetary base remain 0.5. The capital call imposed with loss-born control therefore removes the very control needed to approve the next bailout.

Build 76 writes durable assessment markers onto the underlying Build 75 credit. If isolated v76 state is missing while older quota, reserve-pool, and loss-credit state survives, Build 76 reconstructs the assessment ledger and aggregate paid/request counters from those markers without collecting reserves or granting quota a second time. The recovery harness rebuilt a paid `SRA7` 10.0 assessment while leaving the already-persisted A quota and Build 58 pools unchanged.

Build 76 persists through `nothing-state-v76`, wraps the existing save/render chain, loads after `loss_quota.js`, and extends forget-through-v76. It reads and selectively updates Build 56 foreign reserves, Build 57 trade context used in quota scoring, Build 58 reserve pools/quotas/contribution history, Build 59 director votes and motion history, and Build 75 loss-quota credits. It does not alter Build 74 transfer history or reverse the reserve loss that originally created the creditor's quota.

New places include `majority creditor ordering the bailout target to refill the institution`, `forced reserve payment buying back the votes that imposed it`, `foreign reserves seized by the institution and returned as voting capital`, and `debtor paying an assessment that makes the creditor less dominant`. `replenishment.js` passes V8 syntax validation. The instrumented harness executes the exact committed Build 76 functions and covers full collection, partial arrears, reserve stress, majority reversal, insufficient-majority refusal, marker recovery, and the Build 74 deadlock that returns after the creditor majority is lost.
