# Build 72

Public clawback acquired liens. Build 71 gave the public side a recoupment claim when a Build 70 monetary make-good was followed by a later private recovery. Cash collection worked when the rescued Build 63 fund still had money, but a partial or arrears claim could remain unpaid after the fund spent or pledged its cash. Build 72 converts that unpaid public claim into a persistent property interest through the Interreality Public Recovery Lien Registry.

A Build 71 claim in `due`, `partial`, or `arrears` can now support one or more `PLI#` liens against Build 63 fund positions. The lien is sized only to the portion of the public claim not already covered by current fund cash. The registry prefers clean unencumbered assets first, then assets already subject to a Build 64 repo or Build 65 reuse chain, and title-disputed assets last. This makes public enforcement follow the actual balance sheet instead of attaching arbitrary paper.

Build 72 does not give the government magical superpriority. Every public lien is `junior-statutory`. An existing Build 64 repo stays senior. An active Build 65 rehypothecation chain stays senior. An open Build 65 title dispute also stays senior. A lien on clean paper is `perfected`; a lien behind repo or reuse becomes `subordinate-secured`; a lien behind an unresolved title dispute becomes `subordinate-title`. Subordinate liens cannot be directly levied while the private interest survives.

Perfected public liens block an open Build 63 market listing. The block occurs in the same Build 72 reconciliation pass that creates the lien, preventing the fund from listing the asset during the gap between attachment and the next timer tick. If an older layer later creates a repo against the asset, Build 72 does not rewrite the old repo transaction; instead the public lien becomes subordinate to that secured position and waits for residual proceeds.

A clean perfected lien can be levied. Build 72 marks the asset using the late distressed-collateral factors already present in the stack: Build 63-style claim/bond ratios, active Build 61 lien effects, reserve coverage, arrears, payment injunctions, Build 64 fire-sale shocks, and Build 65 title-freeze discounting. A forced public sale occurs at 72% of that marked value. Another Build 63 fund must have enough cash to buy the paper. The buyer pays the full levy price and becomes the actual Build 63 owner. The public claim receives no more than the lien's secured amount, the Build 71 outstanding claim, and the live Build 55 facility principal. Any excess sale price returns to the old fund as surplus.

Public levy proceeds retire the same balance sheet that Build 71 cash collection retires. Build 72 reduces the linked Build 55 facility principal, the monetary authority's monetary base and outstanding credit, and the Build 55 reserves-extinguished total. It also records a normal Build 71 `PRP#` recoupment-payment record with a Build 72 source marker so later layers do not need a parallel public-credit ledger. If principal falls to zero, old accrued Build 55 interest still survives exactly as in Build 71.

Private secured liquidation remains senior. If a liened asset is already inside a Build 64 repo and that repo later liquidates, Build 72 waits until the old repo waterfall has run. It may collect only the liquidation surplus that Build 64 actually returned to the original fund. If Build 65 leaves a surviving title dispute on the asset, Build 72 treats the public claim as still junior and collects zero from that nominal Build 64 surplus. The public lien is then released from the sold asset rather than following the buyer ahead of the older title claim.

The same proceeds rule applies to a liened Build 63 claim that settles voluntarily. Build 64 gets its existing collateral-proceeds sweep first when a repo is active. Build 72 then takes no more than the remaining cash actually present in the original fund and the public lien's secured amount. The historical sovereign settlement, repo sweep, public recoupment claim, and public lien all remain distinct records.

Build 72 also introduces a narrow fund-distress classification without creating a bankruptcy system. For each live Build 71 recoupment claim, it compares the fund's cash plus the marked value available behind senior repo/title claims with the public amount still outstanding. If that junior value is insufficient, the fund is marked `publicRecoupmentDistress72='insolvent'`. This is an observation and trigger for future builds; Build 72 does not invent a bankruptcy estate or creditor voting process.

The deterministic clean-lien harness used a 2.0 exchange bond owned by Clearing Yield Cooperative and a 0.52 outstanding public recoupment claim. The current Build 72 mark was 1.5018181818. A public levy sold the bond to Rift Mutual Credit for 1.0813090909, or 72% of mark. Exactly 0.52 retired the Build 71 claim and linked Build 55 public facility, monetary base and outstanding credit all fell to zero, the claim became `paid`, and the remaining 0.5613090909 sale surplus returned to the old fund.

The secured-priority harness put a 1.0 active Build 64 repo on the same asset. The public lien became `subordinate-secured` and direct levy returned no sale. After a Build 64 liquidation produced 0.40 of actual surplus for the old fund, Build 72 collected exactly 0.40, leaving 0.12 of public claim, Build 55 facility principal, and monetary base still outstanding. A variant with a surviving Build 65 title dispute collected zero from the same nominal repo surplus.

The title harness put 1.20 of open Build 65 title dispute ahead of the public claim. The lien became `subordinate-title` and could not be levied. The listing harness confirmed an already-open Build 63 listing is immediately changed to `blocked-public-lien` when the lien is perfected. The insolvency harness used only 0.0750909091 of junior available asset value against a 0.52 public claim and marked the fund publicly insolvent.

Build 72 persists through `nothing-state-v72`, wraps the existing save/render chain, loads after `public_recoupment.js`, and extends forget-through-v72. It reads and selectively updates Build 55 public credit, Build 61/57/56 valuation inputs, Build 62 claims and bonds, Build 63 funds/listings/ownership, Build 64 repos/liquidations, Build 65 rehypothecation/title disputes, and Build 71 recoupment claims/payments. Historical Build 70 rescue events and Build 69 clearing settlements remain intact.

New places include `the bailout collector arrived after the repo lender and found the same asset`, `public money learned that secured creditors had already numbered the doors`, `distressed claim sold by the public collector instead of its fund owner`, and `a private recovery asset disappeared into a central-bank repayment receipt`. `public_liens.js` passes V8 syntax validation. The instrumented harness executes the actual Build 72 functions and covers clean lien perfection and levy, immediate listing blocks, repo subordination and surplus sweep, surviving-title priority, title-dispute levy refusal, and public fund-insolvency classification.
