# Build 65

Collateral acquired more than one owner. Build 64 let a Build 63 investment fund borrow against a distressed claim or exchange bond while retaining economic ownership of the asset. Build 65 adds an Interreality Collateral Title Registry above that repo layer and asks the next consequence: once the lender possesses an encumbered asset, what prevents the lender from borrowing against the same collateral again?

An active Build 64 repo can now be rehypothecated. The original fund remains the beneficial owner. The Build 64 lender remains the first repo lienholder. But that lender can re-pledge the same claim or exchange bond to another clearing house, or to the Build 65 registry liquidity desk when no second clearing house is available. The downstream lender advances cash to the first lender rather than to the fund. No sovereign debt face value changes. What changes is title: one asset now supports an ownership interest and two secured promises at the same time.

Build 65 records that stack explicitly with title certificates. The beneficial owner is recorded behind the first repo lien, and the downstream rehypothecation lien is recorded senior to both. Reuse capacity is still mark-to-market, but Build 65 adds another 12 percentage points of secured-lending haircut before advancing downstream cash. A first lender can therefore convert a Build 64 collateral position into new general liquidity even though it never bought the underlying claim.

Normal chains can unwind cleanly. When the original Build 64 repo closes, Build 65 automatically recalls the collateral. The first lender repays the downstream advance plus a 1.2% reuse fee, the downstream lien is released, the title certificates close, and the original fund again owns an unencumbered asset. In the deterministic harness, a 9.36 exchange bond supporting a 5.1295 Build 64 repo generated about 4.0694 of downstream funding. The clean recall required about 4.1182, leaving the first clearing house with 7.9512 liquidity and the downstream clearing house with 10.0488 after its fee.

The important case is when the original repo ends but the first lender no longer has the liquidity needed to recall the collateral. The fund may have fully repaid its own Build 64 loan and still fail to receive clean title because its lender pledged the asset elsewhere. Build 65 then creates a persistent title dispute and freezes the owner's position. Any Build 63 sale listing that appears while the dispute remains open is automatically changed to `blocked-title-dispute`. The asset cannot silently become free collateral merely because the first repo flag disappeared.

A title dispute can be cured through the first lender's default resources. The registry applies the lender's default fund first and clearing-house capital after that. If those resources retire the downstream claim, clean title returns to the current owner and the frozen position becomes owned again. In the failed-recall harness, the first clearing house had no remaining liquidity after the parent repo closed; recovering clean title required 4.1182 from its default fund. The fund had already repaid, but a clearing default resource still had to be spent before its property could come home.

Build 65 also follows Build 64 forced liquidations. A downstream rehypothecation lien has senior priority to the first lender's available liquidity after the collateral sale. If the first lender cannot satisfy that senior claim from liquidity, its default fund and then its capital are used. If those resources are still insufficient, the Build 64 buyer receives the asset with an unresolved senior lien. The buyer's Build 63 position becomes `encumbered-title` and the asset remains frozen even though the fire sale itself was final.

The liquidation harness deliberately exhausted the first clearing house. After rehypothecating the same 9.36 exchange bond, the first lender was left with only 0.2 liquidity, 0.1 default fund, and 0.1 capital before the Build 64 liquidation appeared. Build 65 swept the available 0.2 to the downstream lender, exhausted the 0.1 default fund and 0.1 capital, and left about 3.7182 of senior title unresolved. Rift Mutual Credit had bought the bond, but its new position was immediately marked `encumbered-title`. The sale transferred possession without delivering clean ownership.

This creates a deliberately uncomfortable distinction between economic ownership, possession, and priority. The original fund can own the asset, the first lender can possess it, the downstream lender can hold the senior lien, and a fire-sale buyer can later hold the paper while still not holding clean title. New places include `lender borrowed against collateral it did not own`, `same asset on two balance sheets as available security`, `the owner repaid the loan but the collateral was somewhere else`, `sale proceeds went to a creditor the buyer never negotiated with`, and `one promise wore three name tags and every name tag said senior`.

Build 65 persists through `nothing-state-v65`, wraps the existing save/render chain, loads after `repo_finance.js`, and extends the forget action through version 65. It reads and selectively updates Build 54 clearing-house liquidity/default funds/capital, Build 61 lien state, Build 62 claims and exchange bonds, Build 63 fund ownership/listings, and Build 64 repo loans/liquidations. Historical trades, settlements, repo contracts, and liquidation records are not rewritten. Build 65 adds the title consequences that appear after those records already exist.

`collateral_title.js` passes Node syntax validation. The deterministic harness covers clean recall, failed recall and default-fund cure, title freezing, blocked resale, and a liquidation where a surviving senior rehypothecation lien follows the asset into the buyer's portfolio.
