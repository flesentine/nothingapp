# Build 78

FX rebalancing acquired sterilization. Build 77 fixes stabilization-fund currency mismatch by returning an overweight settlement currency to its issuer and taking the currency the fund actually lacks. That transaction is real, but it also destroys the issuing reality's monetary base. Build 78 lets the old Build 55 monetary authority offset most of that contraction with a temporary, fully collateralized liquidity operation through the Interreality Monetary Sterilization Desk.

Build 78 does not reverse the Build 77 reserve transfer. Foreign reserves that left the issuing reality remain gone, the stabilization fund keeps the currency it acquired, and the historical Build 56 FX trade remains final. Sterilization changes only the domestic monetary side after the FX settlement.

The ordinary policy target is 80% of the Build 77 settlement currency returned to its issuer. A Build 77 trade that retired 5 units of domestic monetary base therefore creates a 4-unit sterilization target. The remaining 20% preserves some of the original tightening.

If the source Build 77 trade already recorded peg stress, the policy target falls to 40%. The monetary authority deliberately leaves more contraction in place rather than completely neutralizing a trade that was already pushing against an exchange-rate commitment.

Sterilization liquidity must be backed by existing Build 55-eligible collateral. Build 78 searches the same borrower classes that Build 55 already knows how to govern: solvent Build 53 derivative dealers, operating Build 54 clearinghouses, solvent Build 51 insurers, and viable Build 47 package treasuries. It uses the current Build 52 rating when available, the Build 55 collateral floor, and the same grade haircut schedule.

Available collateral is the borrower's haircut-adjusted collateral value less principal already outstanding through active Build 55 facilities. Build 78 can split one sterilization target across multiple eligible borrowers, but it never issues more than the collateral capacity currently available.

Each successful allocation creates a real Build 55 `LF#` liquidity facility, a real Build 55 reserve account if the borrower does not already have one, increases the borrower's actual Build 55 cash field, increases the issuing authority's monetary base and outstanding credit, and increments the existing Build 55 reserves-issued total. The facility is tagged with its Build 78 sterilization and Build 77 source records, but otherwise remains an ordinary active Build 55 loan.

The Build 55-compatible facility uses the authority's discount rate plus 0.5 percentage point, matures on the ordinary Build 55 emergency-loan horizon, carries the same collateral type/grade/haircut fields, and is deliberately not issued under a solvency or collateral override. Old Build 55 accrual, revaluation, collateral-call, repayment, evergreen, and monetization machinery therefore remains authoritative after issuance.

A monetary authority already marked `negative-equity` cannot perform ordinary Build 78 sterilization. The request becomes `blocked-negative-equity`. An explicit emergency override can still proceed if eligible collateral exists, but Build 78 reduces authority independence by 0.04 and credibility by 0.03 and records a monetary-sterilization crisis. Negative equity therefore changes governance, not the collateral rule.

Insufficient collateral creates a real partial sterilization rather than unbacked liquidity. A request that initially issues some reserves becomes `partial-collateral`; a later retry with no newly available collateral can become `blocked-collateral`. Aggregate shortfall and block counters are retry-safe, so repeating the same unresolved request does not inflate the reported loss.

Sterilization also feeds back into the real Build 56 market. Recreating domestic liquidity after an FX reserve redemption weakens the same currency whose supply contraction Build 77 had just produced. Build 78 therefore adds a smaller second price impulse in the same direction as the source Build 77 trade. Selling RB for RA in Build 77 raises `RA/RB`; recreating some RB liquidity in Build 78 raises it a little further. The inverse holds for an RA sterilization.

The deterministic ordinary harness starts after the canonical Build 77 Reality B operation. B monetary base is 15 after 5 RB were retired, `RA/RB` is 1.0225, and a solvent Build 53 dealer has 10 capital plus 10 collateral. Build 78 targets 4.0, issues one fully collateralized Build 55 facility for 4.0, raises B monetary base 15→19, raises B outstanding credit 0→4, raises the dealer's capital 10→14, credits a Build 55 reserve account with 4, and increments Build 55 reserves issued by 4. The Build 77 reserve loss remains: B still has only 7 RA of foreign reserves. The second liquidity impulse moves `RA/RB` 1.0225→1.0286006837.

The peg-constrained harness uses the same 5-unit Build 77 contraction but marks the source trade as having stressed a peg. Build 78 targets only 2.0, issues 2.0, and moves B monetary base 15→17. One peg-constrained sterilization is recorded.

The collateral-shortfall harness gives the only eligible dealer just 2 capital and no posted collateral. Build 55's BBB haircut leaves only 1.64 of lendable value. Build 78 issues exactly 1.64 against a 4.0 target and leaves 2.36 unresolved. A retry with no new collateral does not increase the 2.36 aggregate shortfall or duplicate the block counter.

The negative-equity harness begins with the Reality B authority already marked `negative-equity`. Ordinary execution issues zero and leaves monetary base at 15. The emergency override then issues the full 4.0, restores base to 19, reduces independence 0.82→0.78 and credibility 0.76→0.73, and records one override.

The exact Build 77→78 cross-build harness begins from the canonical 5 RA / 15 RB stabilization mismatch. Build 77 sells 5 RB for 5 RA, leaving the fund at 10/10, B foreign reserves 12→7, B monetary base 20→15, and `RA/RB` 1.0000→1.0225. Build 78 then issues 4.0 of collateralized sterilization credit. Final B monetary base is 19, outstanding credit is 4, dealer capital is 14, the reserve account holds 4, Build 55 reserves issued are 4 while Build 55 reserves extinguished remain 5 from the FX redemption, and `RA/RB` reaches 1.0286006837. The reserve transfer is intact while 80% of its domestic monetary contraction has disappeared.

The old Build 55 compatibility harness then loads that exact sterilization facility into the exact committed Build 55 code. Build 55 revaluation updates the dealer-backed collateral face from 13.5 to 14.9 and lendable value to 12.218, with no collateral call. One minute of ordinary Build 55 accrual adds roughly 0.008 interest. Repaying the facility through the old `repayFacility` function returns monetary base 19→15, outstanding credit 4→0, reserve-account balance 4→0, marks the facility `repaid`, increases authority capital by the accrued interest, and raises the cumulative Build 55 reserves-extinguished total from 5 to 9.

Build 78 persists through `nothing-state-v78`, wraps the existing save/render chain, loads after `reserve_rebalance.js`, and extends forget-through-v78. Its authoritative recovery marker is the Build 55 facility itself. If isolated v78 state is missing while the tagged Build 55 facilities survive, Build 78 reconstructs its `MSO#` ledger, targets, issued totals, shortfalls, facility counts, override count, and serial without issuing liquidity again.

New places include `central bank lending back the money the stabilization fund just retired`, `FX tightening sterilized with collateralized software credit`, `temporary collateralized liquidity replacing money retired by stabilization FX`, and `central bank neutralizing its own reserve-redemption tightening`. `monetary_sterilization.js` passes V8 syntax validation.
