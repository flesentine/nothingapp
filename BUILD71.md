# Build 71

Public rescue acquired recoupment. Build 70 allowed the old Build 55 monetary authority to create settlement reserves after a Build 69 recovery-protection settlement was already final with a shortfall. The public make-good could economically cure the fund's unpaid hedge while preserving the historical `final-with-shortfall` record. Build 70 also deliberately preserved the later private Build 67 recovery stream, producing a new event in which a fund could receive public money because its hedge failed and then later receive the private recovery anyway. Build 71 gives that public/private overlap a balance-sheet consequence through the Interreality Public Recoupment Office.

Every Build 70 public-double-recovery event can now generate one persistent `PRC#` public recoupment claim. The gross claim is bounded by the smaller of the public make-good and the later private recovery. The collectible amount is bounded again by the principal still outstanding on the exact Build 55 recovery-bridge facility that financed the public make-good. This prevents the public side from clawing back more money than the investor actually received through the rescue or retiring more public credit than still exists.

The claim is attached to the Build 63 fund that received the public make-good and later recovery. It also remembers the Build 70 make-good, Build 69 settlement and position, Build 67 recovery note, Build 55 facility, monetary authority, and reality. A claim has a short deadline. If it remains unpaid after the deadline it becomes arrears without changing the underlying Build 70 public-double-recovery history.

Collection is a real cash-flow event. The Public Recoupment Office takes no more than the fund's available cash and no more than the claim or linked facility principal. The same amount reduces the Build 55 facility principal, the existing monetary authority's monetary base, and its outstanding credit, and increments the old Build 55 reserve-extinguishment total. If the facility principal reaches zero, Build 71 marks that principal as recouped. If no Build 55 interest remains, the facility becomes `repaid-by-recoupment`; if interest had already accrued, the facility remains active for that older interest claim rather than silently forgiving it. Public recoupment therefore does not merely move a counter on a new layer: it can actually reverse part or all of the monetary expansion created by Build 70 while preserving pre-existing interest.

Partial collection is persistent. If the fund has less cash than the public claim, the available amount is collected, public credit shrinks by that amount, and the claim remains `partial` for the balance. If the fund has no cash, the claim enters `arrears`. This leaves a natural future path for collection liens, fund insolvency, or priority disputes without adding those systems in Build 71.

A linked Build 55 rescue can also disappear before recoupment. If the facility exists but its monetary-authority record is missing, the claim becomes `orphaned-authority` and collection stops before fund cash moves. If the CCP or another mechanism has already repaid the public facility, Build 71 marks the claim `moot-public-credit-repaid` and sets the collectible balance to zero. The later private recovery still happened, but the public balance sheet has already been restored, so the system does not double-collect merely because a Build 70 public-double-recovery event exists.

The user can waive a due, partial, or arrears claim. Waiver leaves the linked public facility outstanding and lets the fund keep the later private recovery. The monetary authority loses independence and credibility and gains another emergency-mandate count. The waiver remains a historical policy choice rather than silently pretending the clawback never existed.

The deterministic full-recovery harness uses the Build 70 main path: a 0.72 public make-good, a 2.2110784 later private recovery, and a still-outstanding 0.72 Build 55 recovery facility. Build 71 issues a 0.72 claim. With enough fund cash, collection transfers 0.72 from the Build 63 fund, reduces the facility from 0.72 to zero, reduces monetary base and outstanding credit from 0.72 to zero, increments Build 55 reserves extinguished by 0.72, and marks the facility `repaid-by-recoupment` when no interest remains and marks the claim `paid`.

A partial harness gives the same claim to a fund with only 0.20 cash. Build 71 collects 0.20, leaves 0.52 of facility principal and monetary base outstanding, and keeps a 0.52 partial public claim. A mootness harness starts with the linked Build 55 facility already repaid; the event still produces a historical recoupment record, but the claim is immediately `moot-public-credit-repaid` with zero collectible balance. A waiver harness leaves the public facility principal untouched while recording the decision to abandon the clawback and reducing monetary-authority credibility and independence.

Build 71 persists through `nothing-state-v71`, wraps the existing save/render chain, loads after `recovery_monetary.js`, and extends the forget action through version 71. It reads and selectively updates Build 55 facilities, reserve accounts, monetary base and credit, Build 63 fund cash, and Build 70 make-good/double-recovery records. It does not reverse Build 70 rescue history, Build 69 clearing finality, Build 68 protection settlements, Build 67 recovery, Build 66 subrogation, or Build 65 title history.

New places include `public money asking for itself back after private recovery succeeded`, `central bank balance sheet shrinking because an investment fund paid the bailout back`, and `rescued investor received a clawback notice after recovery succeeded`. `public_recoupment.js` passes V8 syntax validation. The instrumented harness executes the actual Build 71 functions and covers full collection, partial collection, no-cash arrears, already-repaid facility mootness, waiver, facility retirement, monetary-base retirement, and Build 55 reserve extinguishment.
