# Build 45

Provenance acquired a dependency ecosystem. Every Build 44 artifact now receives a persistent software bill of materials that resolves named direct and transitive packages from Reality A or Reality B registries, including packages such as `runtime-policy`, `quorum-client`, `identity-parser`, `archive-codec`, and `rift-core`. Package versions have maintainers, registry identities, dependency edges, integrity values, publication history, yanks, patches, and compromise state. SBOMs are attached to artifact hashes rather than source labels, so two binaries claiming the same source can expose different dependency trees.

Vulnerability advisories can be disclosed against a package already present inside correctly signed and reproducible artifacts; the artifact's provenance remains valid while its status becomes known-vulnerable. Publishing a patched package changes future resolution but does not remove the vulnerable version from already deployed binaries. Live remediation therefore creates new Build 44 artifacts with new dependency locks, hashes, provenance attestations, and SBOMs while preserving the old vulnerable binaries in history. Yanking a package likewise removes it from future resolution without uninstalling it from production.

Maintainer compromise can publish a newer hostile package under the expected package identity, and that compromised release remains resolvable until explicitly yanked. Reality A and Reality B can also suffer dependency confusion: a same-named package from the other reality or a shared interreality registry can publish an artificially high version and win resolution, causing new signed artifacts to import a foreign package without changing their source ref.

Dependency advisories can be exploited against a currently deployed replica, mutating that replica's executed state even though the artifact, provenance chain, and SBOM are all accurate; this creates a transitive-compromise incident rather than pretending the binary was forged. Build 45 therefore separates source identity, artifact identity, dependency contents, package authority, vulnerability status, and executed behavior.

Build 45 tracks package registries, maintainers, versions, dependency graphs, SBOMs and SBOM digests, vulnerability advisories, vulnerable artifacts, patched versions, live rebuild remediation, yanks, maintainer compromise, dependency confusion, cross-reality packages, transitive exploits, dependency incidents, and dependency crises, with places such as `signed binary with an accurate vulnerable SBOM`, `foreign package won by version number`, `one-line dependency beneath constitutional machinery`, and `software bill of materials became a chain of command`, leaving the bailiff asking who elected the transitive dependency.
